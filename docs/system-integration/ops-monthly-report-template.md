> 模块：系统集成与交互体验  
> 负责人：苗文昊（System Integrator & UI/UX）

## 一、设计思路说明

### 1.1 为什么需要运维月报

本项目对 LLM 调用、外部 API 调用、向量库查询等成本敏感型资源有持续支出。若不建立月度对账机制，将出现以下问题：

- Token 消耗失控但无人察觉，到月底才发现超预算
- 模块故障率上升无法及时归因到具体责任人
- 用户行为数据（高频意图、热门查询）未被沉淀，无法反哺产品迭代
- 答辩或交付时无法用数据证明"系统稳定运行"

因此，集成端必须输出一份**结构化、可填空、自动化生成**的月报模板，作为本系统运维体系的"对账凭证"。

### 1.2 核心设计原则

- **模板化优先**：所有指标固定位置、固定单位，便于跨月对比
- **数据驱动**：所有数字必须可追溯到具体 SQL 查询，禁止"拍脑袋估算"
- **责任到人**：故障与超额必须归因到具体模块负责人，体现"全权负责制"
- **可自动化生成**：未来可通过定时任务自动填充本模板的 80% 字段
- **轻量可读**：单份月报控制在 3-5 页内，重点突出，不堆数据

### 1.3 月报结构总览

- **第一部分**：执行摘要（一句话总结本月）
- **第二部分**：核心指标看板（5 个 KPI）
- **第三部分**：模块级运行情况（4 个模块分项）
- **第四部分**：成本与 Token 审计
- **第五部分**：故障与降级事件复盘
- **第六部分**：用户行为洞察
- **第七部分**：下月行动项（Action Items）

### 1.4 数据来源对照

- 调用次数、意图分布、降级率 → `agent_session_logs` 表
- Token 消耗、模型成本 → `token_usage_logs` 表
- 模块健康度 → `GET /api/v1/admin/health` 的历史采样
- 用户活跃度 → `user_profiles.last_active_at`
- 数据规模 → `novels` / `raw_reviews` 表的行数统计

| P95 延迟（ms）                 | 【____】 | 【____】 | 【__%】  | ≤ 5000   | 【✅/⚠️/❌】 |
| Fallback 触发率                | 【__%】  | 【__%】  | 【__pp】 | < 5%     | 【✅/⚠️/❌】 |
| LLM 总成本（USD）              | 【____】 | 【____】 | 【__%】  | ≤ 50 USD | 【✅/⚠️/❌】 |

**数据来源 SQL：**

```sql
-- 总请求数
SELECT COUNT(*) FROM agent_session_logs
WHERE created_at >= '【月初】' AND created_at < '【次月初】';

-- 可用率（status != 'failed' 占比）
SELECT 
  ROUND(100.0 * SUM(CASE WHEN status != 'failed' THEN 1 ELSE 0 END) / COUNT(*), 2) AS availability_pct
FROM agent_session_logs
WHERE created_at >= '【月初】' AND created_at < '【次月初】';

-- P50 / P95 延迟
SELECT 
  PERCENTILE_CONT(0.5) WITHIN GROUP (ORDER BY latency_ms) AS p50,
  PERCENTILE_CONT(0.95) WITHIN GROUP (ORDER BY latency_ms) AS p95
FROM agent_session_logs
WHERE created_at >= '【月初】' AND created_at < '【次月初】'
  AND status IN ('success', 'partial');

-- Fallback 触发率
SELECT
  ROUND(100.0 * SUM(CASE WHEN status = 'fallback' THEN 1 ELSE 0 END) / COUNT(*), 2) AS fallback_rate
FROM agent_session_logs
WHERE created_at >= '【月初】' AND created_at < '【次月初】';

-- LLM 总成本
SELECT SUM(cost_usd) AS total_cost
FROM token_usage_logs
WHERE occurred_at >= '【月初】' AND occurred_at < '【次月初】';
```

## 三、模板使用说明（给负责人）

### 3.1 月度填报流程

- **每月 1 日 00:00** —— 自动归档上月数据快照
- **每月 1 日 02:00** —— 定时任务执行 SQL，生成数据填充版草稿
- **每月 1 日 09:00** —— 集成端负责人（苗文昊）审阅草稿，补充文字描述
- **每月 2 日 18:00** —— 与各模块负责人对齐"问题与建议"部分
- **每月 3 日 12:00** —— 终版月报发布到团队共享目录

### 3.2 责任分工

| 章节           | 数据填充人   | 文字补充人   |
| -------------- | ------------ | ------------ |
| 一、执行摘要   | 苗文昊       | 苗文昊       |
| 二、KPI 看板   | 自动 SQL     | 苗文昊       |
| 三、模块级情况 | 自动 SQL     | 各模块负责人 |
| 四、成本审计   | 自动 SQL     | 苗文昊       |
| 五、故障复盘   | 各模块负责人 | 各模块负责人 |
| 六、用户洞察   | 自动 SQL     | 苗文昊       |
| 七、行动项     | 全员讨论     | 苗文昊       |

### 3.3 异常告警阈值（触发即邮件通知）

- 端到端可用率 < 95% → 立即告警
- Fallback 触发率 > 10% → 当日告警
- 单日 LLM 成本超日均 2 倍 → 当日告警
- P95 延迟 > 8000ms → 当日告警
- 任意模块连续 3 小时健康检查失败 → 立即告警
